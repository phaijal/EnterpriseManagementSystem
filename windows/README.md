# Windows: ERPNext bench backup & restore

Paths below assume your repo root contains `docker-compose.erpnext.yml`. Open **PowerShell** in that folder (`cd` there first).

---

## Backup (manual, uses ERPNext bench)

Default folder: **`D:\erp backups`** (created if missing). If **`D:`** is not available, falls back to **`<repo>\backups`**.

```powershell
cd C:\path\to\EnterpriseManagementSystem
powershell -ExecutionPolicy Bypass -File .\windows\Backup-Erpnext-Db.ps1
```

Custom folder (example: **D:\erp backups**):

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\Backup-Erpnext-Db.ps1 -BackupDir "D:\erp backups"
```

**Needs:** Docker Desktop running, stack up (`backend` + `db` healthy), and site `frontend` present in ERPNext.

What gets saved (for site `frontend`):
- `*-frontend-database.sql.gz`
- `*-frontend-private-files.tar`
- `*-frontend-files.tar`
- `*-frontend-site_config_backup.json` (when generated by bench)

---

## Backup (daily at 2:00 PM)

Registers task **EMS ERPNext DB Backup** (runs only when you are logged in). **Default backup folder: `D:\erp backups`**.

```powershell
cd C:\path\to\EnterpriseManagementSystem
powershell -ExecutionPolicy Bypass -File .\windows\Register-DailyDbBackup-Task.ps1
```

Use another folder:

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\Register-DailyDbBackup-Task.ps1 -BackupDir "E:\MyBackups"
```

**Change time:** set `BACKUP_TASK_HOUR` before registering, e.g. `9` for 9:00:

```powershell
$env:BACKUP_TASK_HOUR = "9"
powershell -ExecutionPolicy Bypass -File .\windows\Register-DailyDbBackup-Task.ps1 -BackupDir "D:\erp backups"
```

**Keep backups longer:** `RETENTION_DAYS` (default 14), e.g.:

```powershell
$env:RETENTION_DAYS = "30"
powershell -ExecutionPolicy Bypass -File .\windows\Backup-Erpnext-Db.ps1 -BackupDir "D:\erp backups"
```

**List / remove task:** Task Scheduler (`taskschd.msc`) → **Task Scheduler Library** → **EMS ERPNext DB Backup**.

## Restore (MariaDB emptied or new volume)

Backups are bench artifacts for site `frontend` (database + files).

1. Keep the latest backup set together (same timestamp prefix), e.g.:
   - `20260329_223033-frontend-database.sql.gz`
   - `20260329_223033-frontend-private-files.tar`
   - `20260329_223033-frontend-files.tar`

2. Start containers (from repo root):

```powershell
cd C:\path\to\EnterpriseManagementSystem
docker compose -f docker-compose.erpnext.yml up -d
```

3. Copy backup files into backend container backups folder:

```powershell
$prefix = "20260329_223033"   # your backup timestamp prefix
docker compose -f docker-compose.erpnext.yml cp "D:\erp backups\$prefix-frontend-database.sql.gz" backend:/home/frappe/frappe-bench/sites/frontend/private/backups/
docker compose -f docker-compose.erpnext.yml cp "D:\erp backups\$prefix-frontend-private-files.tar" backend:/home/frappe/frappe-bench/sites/frontend/private/backups/
docker compose -f docker-compose.erpnext.yml cp "D:\erp backups\$prefix-frontend-files.tar" backend:/home/frappe/frappe-bench/sites/frontend/private/backups/
```

4. Restore with bench inside backend container:

```powershell
docker compose -f docker-compose.erpnext.yml exec -T backend bench --site frontend --force restore /home/frappe/frappe-bench/sites/frontend/private/backups/20260329_223033-frontend-database.sql.gz
```

5. Restore files:

```powershell
docker compose -f docker-compose.erpnext.yml exec -T backend bash -lc "tar -xf /home/frappe/frappe-bench/sites/frontend/private/backups/20260329_223033-frontend-private-files.tar -C /home/frappe/frappe-bench/sites/frontend/private/files"
docker compose -f docker-compose.erpnext.yml exec -T backend bash -lc "tar -xf /home/frappe/frappe-bench/sites/frontend/private/backups/20260329_223033-frontend-files.tar -C /home/frappe/frappe-bench/sites/frontend/public/files"
```

6. Restart services:

```powershell
docker compose -f docker-compose.erpnext.yml restart backend frontend websocket queue-worker scheduler ui
```

Fallback DB-only restore (without bench): unzip `*-frontend-database.sql.gz` and import with mysql as before. But preferred path is bench restore + file tar extraction above.
